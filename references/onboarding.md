# 访谈、样本与档案维护

## 开始前

阅读已有档案和本轮材料，复用已知信息。只补问真正影响建档或本篇表达的内容。用户来润色时先满足当前任务，不自动引导完整品牌策划、账号定位或知识库建设。

首次可以这样说：“可以给我几段你自己写过的内容，也可以先聊一件你想表达的事。我们会把有依据的习惯记录下来，再用一小段改写让你校准。你不想公开或不想表达的部分也可以直接说明。”已有文章时不重复这段引导。

## 自然表达访谈

一次一个问题，顺着上一轮回答追问。不是让用户把调查表填满，不先替用户列出观点供选择。已知身份无需重问。根据当前缺口选题：

| 要了解什么 | 提问示例 |
| --- | --- |
| 写给谁、以什么身份说 | “你主要想写给谁看？在他们面前，你更接近平时的哪一种角色？” |
| 自然叙述 | “最近有没有一件你想分享的小事？按你平时聊天的方式讲讲。” |
| 解释方式 | “如果对方第一次听说这件事，你会怎么给他解释？” |
| 判断与分寸 | “有人不太赞同，你会怎样回应？直接说你会说的那段话。” |
| 不像本人的表达 | “有没有一句文案让你觉得自己不会这么说？你会怎么改？” |
| 个人边界 | “有哪些话题、经历、身份，或说话方式，是你希望文章避开的？可以只说类别。” |

用户可以跳过、只给文章或直接试改。通常几轮自然回答便可先建初步档案；不固定次数，不通过追问获取敏感细节。只询问边界类别即可，不要求举出私密原事。

如果用户只给职业和“高端、亲和、真诚”等形容词，将其记为背景／目标偏好，给暂定试改或一个具体表达问题；不能由此认定个人文风。不要纠正用户的自我定位，帮助其把期望变成可观察的表达选择。

## 身份、社会角色和语气

分开了解以下信息，可未知：

- 实际背景：本人自述的工作、行业、经历阶段；只记有用信息，不验证或补造头衔。
- 本次发言角色：例如同行交流、个人使用者分享、教师给家长说明、负责人对团队沟通。
- 读者关系：熟人／陌生人、同行／新手、责任关系和专业信息差。
- 呈现范围：哪些身份可写，哪些只帮助内部理解；是否明确代表组织发言。

“董事长”不自动导出强势语气，“老师”不自动导出训导口吻。同一职业的人可能完全不同；同一个人面对团队和读者也可能不同。角色帮助选择称呼、术语解释、正式程度和信息顺序，风格本身由表达证据和明确偏好决定。未经授权不写“代表公司”“作为资深专家”，不把个人判断包装为机构立场。

## 文章样本学习

建议从少量有代表性的片段开始；用户愿意时可补到 5—10 段、覆盖不同用途，这不是最低门槛或效果保证。不要让用户为了凑数量重交已有内容。

记录来源 ID／标题／可用的链接或文件位置、材料归属与场景。用户明确说是本人文章即可采用，不反复验证身份；来源不明才标“待辨明”。本人修改过的 AI 稿优先分析修改处，未改部分不能自动转为本人风格证据。用户直接认可 AI 稿只说明本稿可接受，不等同原作证据。

语音自然回答可以体现措辞、口语句式和态度；先区分有表达作用的语言与只用于停顿、卡顿、自我打断的转写噪声。口头表达不能自动代表正式书面文风，转写也不提供音色／语速依据。引述、反问、假设不是本人立场或经历。

只沉淀语言层面的内容，每条指向具体措辞或可观察的口吻：

- 常用词和短语：如“我觉得、比较、不太、比如说”，记录实际表达作用，不仅统计次数。
- 有作用的口头表达候选：例如某种称述、缓和、强调或拉近读者距离的说法；候选不等于已经证实的稳定口头禅。
- 语气和程度：判断留多大余地，直接或委婉，情绪强弱；不改变目标文本事实的确定程度。
- 句子层面的口语感、长短和节奏：依据实际句子，不从一次回答推断所有文章的句式。
- 称呼与读者距离：只采用已有表达或明确要求，不由职位生成。

例如：“用‘比较／不太’表达对个人体验的程度判断；证据 A ‘比较顺手’、B ‘不太习惯’；适用体验评价；重复观察。不能因此把明确日期或已确认事实写模糊。”

文章的起承转合、先原因后结果、模块拆分、论证顺序、业务流程和排版不属于讲话特征。不能把“样本 A 在讲做饭步骤、B 在讲养花步骤”归纳成“本人文章要按先后步骤写”。“比如说”可作为措辞观察，但“必须先判断再举例”不是同一回事。具体任务明确要求结构整理时单独处理本次内容，不并入讲话档案。

### 口头表达与转写噪声

| 输入中的现象 | 如何处理 |
| --- | --- |
| “嗯、呃”、重复起头、改口、没有信息的重复量词 | 排除，不写入可模仿的口头禅 |
| “比如说”确实引出已有例子，“我觉得”表达本人判断 | 可记录具体用法与证据；不强制每篇或每段出现 |
| “吧、嘛、的话、就是、其实” | 判断本句是否承担语气／指代／衔接作用；仅填停顿时清理，有作用时按需要保留，不能只凭出现次数给出固定结论 |
| 主题词如工具名、产品术语、菜名 | 只作样本语境，不当作跨内容的个人口吻 |

同一人在不同内容中的材料用来补充、限制或修正同一份语言档案。只有在不同场景有一致证据时，才提出跨话题倾向；没有足够材料时如实说暂未识别到稳定口头禅，不编一套“独特标签”。

没有出现的写法只记“样本未见”，不能写成“永不使用”。多个独立表达一致时可记重复观察，不把同篇转载算新证据。用户明确偏好独立记录，即使现有样本不一致也可作为目标要求；列出适用范围，不悄悄抹去反例。外部作者参考标为“目标参考”，不能冒充已经学到用户本人文风。

## 保存与校准

按 [档案模板](../assets/profile-template.md) 填入有依据的内容。未知保留未知；删除不需要的空表行，不为了完整而追问。档案中的身份与隐私字段不能默认进成稿。敏感原句一般不放档案，只记抽象边界；确需记详细证据时先遵守用户给定保存范围。

已有当前项目时，在默认 `.voice-polisher/profiles/<profile-id>/profile.md` 保存或更新；实际工作目录不同就用明确指定位置。首次默认保存时把 `.voice-polisher/` 添加到该项目 `.gitignore`（已有覆盖则不重复，不改其他规则），并说明路径。这里只是帮助避免误提交，不是多人权限系统。不创建与本任务无关的索引或工作台记录。

用本轮目标文本或一小段不含新事实的示例试改，询问具体哪句像／不像。若用户已要求直接交付，本轮可以先交付，不以等校准为由阻塞。状态保持“初步／待校准”；只有用户针对试改明确认可后，才能记录“本次校准获认可”，不推广为所有场景都已验证。

校准重点是“这句话你会不会这样说、哪个词不像你”，不要求使用者认可某套文章逻辑。用户纠正档案偏向内容结构时，撤下这些结构条目，按语言证据重整，不只是更换条目名称。

## 反馈与边界更新

先判断用户修改属于：事实纠正、本篇要求、长期偏好、边界变更。事实纠正只改相关事实；“这次／这篇”只在本篇生效；明确“以后都”直接记录为长期要求，含义清楚无需再确认。

一次无范围的表达修改记单次观察；反复同类修改补证据。不能把每次接受的 AI 输出当作新原创样本，防止档案变成自我循环。没有新证据时不凑新增规则，不自动重建整份档案。

边界记录范围（内部理解／可公开）、适用场景、来源及时间。当前指令明确临时放开某边界时仅临时执行，不改长期范围；明确永久修改才更新长期档案。模糊冲突时举出受影响的一句询问，其他独立部分可以先做。不重复展示用户禁止公开的敏感原事。

支持查看、更正和删除指定记录；删除时同时移除档案内的对应证据摘录和规则，不虚称已删除其他未操作文件或平台中的副本。
